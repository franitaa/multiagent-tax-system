# AI-use disclosure

The six team members used AI assistants throughout the project, and the product itself uses an AI model in one place. **During development**, most of the code, tests and documents were drafted with Claude Code (Claude Sonnet 5.5 for Francesca and Sahana, Claude Opus 5.5 for Supriya and Shruti, with part of Sahana's Oct 30 session on Claude Haiku 5.5), and some with ChatGPT/Codex (JiWon's extraction component and the first version of Sahana's Computation, and Matthew's code review, test drafting and debugging, plus a Claude Opus 5.5 session in the Claude in Chrome side panel for his documents). Between them the assistants generated the orchestration graph, runner, human gate and context strategy (Francesca); the Intake interview, its safety alarms, the taxpayer chat and the draft form (Supriya); the Rules agent and its tests (Matthew); Computation, provenance and security checks (Sahana); the Review/Audit agent, CI, Docker and Docker Compose, the evals, the demo write-ups, `run.py` and the grader and implementation notes (Shruti); and W-2 extraction, memory and the shared extraction service (JiWon), together with the reviews, pull-request descriptions and documents that go with them; most code commits carry a `Co-Authored-By` line naming the assistant. **In the running system**, AI is used for one task only: a vision model (OpenAI, default `gpt-5.4-mini`, or Anthropic, default `claude-sonnet-4-6`, whichever key is in the local `.env`) transcribes the boxes of a synthetic W-2 photo. A volunteer then compares every amount with the photo (`EXTRACTION_REVIEW`) before it is used, and nothing the model returns reaches a tax line without that check. Intake (rules and keyword patterns), Rules, Computation (tax-math tools served over MCP) and Review are deterministic Python; every dollar amount carries a provenance record; the system never gives tax advice and never files anything, and only fictional documents and test SSNs (900 to 999) are accepted. **How the AI output was checked:** each person read, ran and approved what their assistant produced before it was committed; the code was exercised by 1,376 automated tests (pytest, Python 3.11, run in CI and in Docker) and 15 evaluation cases, many new tests were first run against the old code to confirm they fail without the fix, every change went through a pull request that a teammate reviewed by merging it with `main` in a scratch copy and re-running the tests,, and the two demo cases were run through the chat and dashboard code (with an offline stand-in for the vision model) and written up as click-by-click steps. **Known limits:** assistants made mistakes that review caught (for example tests that passed without the fix, merge conflicts left in a commit, and wrong claims about CI behaviour), so the team's own checks, not the assistants' statements, are the evidence; the live extraction was verified with both an OpenAI key and an Anthropic key (`scripts.verify_chat_extraction`, Oct 30); Intake's safety alarms are keyword patterns and can miss unusual wording; model-assisted screening cannot guarantee that a real identifier would be blocked, which is why only fictional documents are allowed. The per-person, per-session record of what each assistant generated and what each person decided or checked is in [AI_USE_LOG.md](AI_USE_LOG.md), and the unexecuted checks for the extraction component are listed in [VALIDATION.md](VALIDATION.md).
