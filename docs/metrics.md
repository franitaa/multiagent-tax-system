# Context metrics

Generated by `python -m scripts.measure_context --turns 30 --docs 12`. Do not edit by hand.

**Read this first.** Token counts are **estimates**: `ceil(len(json)/4)` of the view each agent was handed. The agents are offline stubs, so no model reported real usage; the numbers measure prompt size, not model cost. The scenario is identical in both modes; only the context strategy changes (`--no-context-strategy` = every agent gets the full state).

**Scenario.** 30 user messages (one graph call each), then 12 documents of about 3 KB of fake text each extracted in parallel, rules, computation, a review that fails once, one revision round, and a passing review. Both modes ended in the same state (status, extracted records, computed lines and facts are identical).

**How to read the ratios.** Most of the total and of the turn-1 gap is raw document text (about 12,408 tokens for 12 documents, from the measured extraction worker view) that the full state carries into every call, so it is a property of this scenario (documents present from the start), not of conversation length. The fairer measure of curve *shape* is the growth per turn: the full state adds the whole new exchange each turn, the scoped view adds only the new fact.

The scoped curve is flatter but **not flat**: every turn adds a structured fact (the stub stores one per answer) and Intake needs all facts so it does not re-ask. The chat window itself is capped at 6 messages. A real Intake that records fewer, distinct facts would grow more slowly; retrieving only the facts relevant to the current question is the next step and is not built.
